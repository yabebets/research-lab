# プロジェクトの README の書き方

README は、そのプロジェクトを知らない人（共同研究者・先生・出願書類の読み手・数か月後の自分）が最初に開くページ。台帳（research.yaml・claims.yaml・runs/）が正本で、README はその**読める要約**。

## 手で書く欄と、台帳から生成する欄

| 欄 | 書き方 | いつ見直すか |
|---|---|---|
| 一言（冒頭の 1〜2 文） | 手で書く。何を明らかにするか | G1、主張の範囲が変わったとき |
| 目的と狙い | 手で書く。何を明らかにするか・なぜ大事か・狙う成果（主張の形・投稿先） | G1、G3 |
| 先行研究との差分 | 手で書く。いちばん近い研究と違い。根拠のノートへのリンク | S1 の文献調査・新規性の確認のあと |
| 方法の骨格 | 手で書く。データ・比較する手法・指標を数行 | G2 |
| 検証状況 | **`rl readme` が生成**（段階・確認ポイント・研究の問い・仮説・主張と証拠・実行の数・次にやること・止まっている理由） | 台帳を更新するたび |
| 主なノート | 手で書く。ノートの一覧と 1 行の中身 | ノートを足したとき |

雛形は `templates/project/README.md`。`rl new` で作られる。

## 決まり

- **問い・仮説・主張・数字は手で書かない。** 台帳に書き、`rl readme` で README に出す。手で写すと必ず古くなる
- **数字は claims.yaml の主張からだけ。** 手で書く欄に結果の数字（成功率・精度・効果量）を書かない。まだ runs/ にない「期待値」「見込み」も書かない。結果を README に出したいときは、runs/ に記録 → claims.yaml に主張と run_id → `rl readme`
- 主張の強さは claims.yaml の `strength`（言い切る／限定つき／探索的）のとおりに出る。`sim_only` の主張を「実機で」と書き換えない
- **README は公開されうる。** 事業化の話・出願の計画・人の評価・連絡先・未公開の共同研究の中身は書かない（ノートに書く）。ライセンスが NC のデータを「同梱」と書かない
- 仮説が空のうち（S2 より前）は、手で書く欄で「検証したい問い」として書く。仮説の形にするのは G2 で `hypotheses` が確定してから
- 「検証状況」の枠（`<!-- rl:auto:start -->` 〜 `<!-- rl:auto:end -->`）の中は手で直さない。次の `rl readme` で上書きされる

## コマンド

```bash
rl readme [name]           # 検証状況の枠を台帳から書き直す（枠がなければ末尾に足す）
rl readme [name] --check   # 書き直さず、台帳と合っていなければ終了コード 1
rl check [name]            # 台帳の確認。README が古いと警告を出す
```

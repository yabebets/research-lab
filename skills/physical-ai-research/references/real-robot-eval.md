# 実機評価のプロトコル

`plan.md` の事前登録に、次の表を埋めて G2 で承認を取る。

| 項目 | 決めること | 例 |
|---|---|---|
| 条件 | 比べる方策・設定 | ACT-50ep / ACT-50ep+触覚 |
| 試行数 | `rl_stats.py trials p1 p2` で計算。最低 20 回、比較なら 50 回以上を目安 | 各 50 回 |
| 初期配置 | 物体の位置・向きの決め方。条件間で同じ配置の表を使う | トレイ左奥の 5×5 格子から乱数表で 50 個 |
| 実施順 | 交互またはブロックごとのランダム | A,B,B,A,… を乱数で |
| 成功の判定 | 文で書く。途中で変えない | 底面の 50% 以上がトレイ内、30 秒以内、休止姿勢に戻る |
| 打ち切り | 1 試行の制限時間、安全のための中断の扱い（失敗に数えるか） | 30 秒。人が止めたら失敗に数える |
| 失敗の分類 | 事前に分類を決める | 把持失敗 / 落下 / 衝突 / タイムアウト / 認識失敗 |
| 環境の固定 | 照明・カメラ位置・背景。毎回の確認方法 | `align_live.py` で ±3% 以内 |
| 記録 | 全試行の動画と、方策の入力・出力のログ | `runs/<run_id>/trials/` |
| 判定者 | 条件を知らない人が判定できるか | 動画を条件を伏せて後から判定 |

## 記録の形式（runs/<run_id>/trials.csv）

```
trial,condition,layout_id,success,failure_type,duration_s,video
1,A,17,1,,12.4,trials/001.mp4
2,B,17,0,grasp_miss,30.0,trials/002.mp4
```

集計は `trials.csv` から機械的に：

```bash
python3 ~/research-lab/skills/ml-rigor/scripts/rl_stats.py wilson <成功数> <試行数>
python3 ~/research-lab/skills/ml-rigor/scripts/rl_stats.py twoprop <kA> <nA> <kB> <nB>
```

## 報告の決まり

- 成功率は「37/50（74%、95% CI 60–84%）」のように、分数・割合・区間をそろえて書く
- 試行数が足りない比較は「傾向」と書き、「上回る」と言い切らない
- 動画は成功だけでなく、代表的な失敗も載せる

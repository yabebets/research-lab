# ロボティクスの道具の選び方

2026 年 11 月時点の目安。バージョンや対応状況は変わるので、使う前に公式のドキュメントと GitHub を確認する。

## 方策（policy）

| 方策 | 向いている場面 | 注意 |
|---|---|---|
| ACT（Action Chunking Transformer） | 少数（数十）のデモで 1 つの課題を覚える。SO-101 では最初の選択肢 | 課題・配置が変わると弱い。カメラ位置の変化に敏感（収録時と評価時でカメラの位置合わせが要る） |
| Diffusion Policy | 動きの多峰性がある課題（どちらからでも掴める等） | 推論が遅め。ステップ数と速度のトレードオフを報告 |
| SmolVLA | 小さな VLA。手元の GPU や小さなクラウド GPU で微調整できる | 言語指示の汎化は大きな VLA ほどではない |
| π0 / π0.5（openpi） | 汎用の VLA を自分のロボットに合わせる。LeRobot にも実装あり | 微調整に A100-80GB 級。推論も GPU が要る。Orchestra `18-multimodal/openpi` |
| OpenVLA-OFT | OpenVLA の高速・高性能な微調整法 | Orchestra `18-multimodal/openvla-oft` |
| GR00T N1 系 | ヒューマノイド・両腕向けの基盤モデル | 対応するロボットの形に注意 |

比べるときは、同じデータ・同じ評価プロトコル・近い計算量で。ベースラインとして ACT は必ず入れると読み手が位置づけやすい。

## シミュレータ

| シミュレータ | 向いている場面 | 計算資源 |
|---|---|---|
| MuJoCo（＋MJX） | 手元の SO-101 環境がこれ。接触のある操作、速い。MJX は GPU で大量並列 | Mac でも動く。MJX は CUDA GPU |
| ManiSkill3 | GPU 並列の操作課題、描画も速い。RL・模倣学習のベンチマーク | CUDA GPU |
| Isaac Lab（Isaac Sim） | 大規模な RL、移動ロボット・ヒューマノイド、写実的な描画 | **RTX 系 GPU 必須**（A100 / H100 は描画できない）。RunPod の RTX 4090 / L40S など |
| Genesis | 高速な汎用物理シミュレータ | CUDA GPU 推奨 |

sim2real の基本：ドメインランダム化（摩擦・質量・遅延・カメラ・照明）、システム同定（実機の摩擦やゲインを測ってシミュレーションに入れる）、観測と行動の空間を実機と揃える（関節角か手先位置か、制御周波数）。

## ベンチマーク

- **LIBERO**：言語指示つきの操作課題群。VLA の比較でよく使われる
- **SimplerEnv**：実機の評価と相関するように作られたシミュレーション評価
- **RoboCasa**：家庭環境の大規模な操作課題
- **CALVIN**：長い手順の言語指示課題
- ManiSkill の課題群

ベンチマークの結果を書くときは、課題の部分集合を選んでいないか（ml-rigor の 5 番）、公式の評価スクリプト・試行数・seed を使っているかを確認する。

## データ

- LeRobotDataset 形式（Hugging Face Hub に置ける）。収録時のカメラ・解像度・fps・関節の校正を `run.yaml` に残す
- デモの質（迷い・やり直しの多さ）と量を分けて記録する。デモの分割（train / val）は配置で分ける（同じ配置の前半と後半で分けない）
- 公開データ（Open X-Embodiment、DROID、LeRobot の公開データ）を事前学習や比較に使うときは、ライセンスを確認する

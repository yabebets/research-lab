## 4. Night loop (`rl night`; `bin/rl` `cmd_night`, `skills/research-lab/references/night-loop.md`, `templates/night-prompt.md`)

Mechanics (enforced in code):
- Lock: `<project>/.night.lock` created with `O_EXCL` (pid inside); removed in `finally`.
- Output dir `<project>/.night/<YYYYmmdd-HHMM>/` with `iter-NN.log` (raw `claude -p` JSON output) and `summary.md` (limits, stop reason, per-iteration minutes/cost and the first 600 chars of the result).
- Each iteration = a **fresh** `claude -p <night-prompt> --output-format json --permission-mode dontAsk --max-budget-usd <per_iter> --allowedTools … --disallowedTools …`, cwd = project, env `RL_NIGHT=1`. No conversation carry-over; sequential, one process at a time.
- Budgets: iterations (default 20); total LLM USD (`--budget-usd`, default `budget.llm_usd_per_night` or 10) summed from each iteration's `total_cost_usd`; per-iteration cap `min(3.0, remaining)`; per-iteration timeout `min(90 min, time left)`; wall clock (default 8 h). Loop stops when remaining budget < $0.5.
- Allowed tools: `Read Edit Write Glob Grep WebSearch WebFetch TodoWrite Skill`, `mcp__codex__codex`, `mcp__codex__codex-reply`, and Bash prefixes `python3 python uv ls cat head tail wc grep find mkdir cp mv`, `git status/diff/log/add/commit/rev-parse`, `ssh rsync scp`, `rl status / rl check / rl gpu`, `sky status/logs/queue/exec`, `latexmk pdflatex bibtex`. Denied: `git push`, `rm -rf`, `sky launch`, `sky down`, `lerobot-record`, `lerobot-teleoperate`, `lerobot-replay`, `curl`, `gh`. The subagent tool (Agent/Task) is not in the allow list.
- After every iteration the wrapper: runs `rl gpu reap`; runs `ledger_errors` (stop: "台帳が壊れた"); compares gate `approved` flags before/after — any gate flipped to approved by the agent is **reverted to false**, a blocker "夜間ループが … を承認に変えたので戻した（承認は人だけ）" is appended, and the loop stops; then stops if any `gates.*.pending`, if `len(blockers)` grew versus loop start, or if no task is `open`/`doing`.
- Pre-check: if any gate is already pending, zero iterations run.
- On exit: appends `{by: night-loop, what: "<dir>: 終了（<reason>）、費用 $X"}` to `research.yaml` `log`.

Per-iteration behaviour (instructed by `templates/night-prompt.md`, not checked):
1. Read `~/research-lab/skills/research-lab/SKILL.md`. 2. Read `research.yaml → claims.yaml → plan.md → runs/`（最新の数件）; "会話の記憶はない。台帳が正本". 3. If a gate is pending, do nothing. 4. Pick the **first** task with `status: open` (or leftover `doing`) whose `depends_on` are all `done`. 5. Read the routed skill and do that one task (GPU only via `rl gpu up`; stats via `rl_stats.py`; citations via `verify_bib.py`; ARIS loop skills resume from their own state files rather than restart). 6. On a stop condition, append `{at, reason, needs}` to `blockers`. 7. Update task status, add newly discovered tasks (sequential ids), one `log` line, `runs/<run_id>/` files, `stage`; run `rl check`; `git add` + `git commit` (no push). 8. Finish with a 3–5 line summary.

Hand-off between sessions is therefore: `research.yaml` (tasks/blockers/log/stage) + `claims.yaml` + `plan.md` + `runs/` + project git history + `.night/<ts>/summary.md` for the human. `rl status` is the morning view.

Search/selection policy inside the loop: strictly "first eligible open task" in a flat list with `depends_on`. No scoring, prioritisation, parallel branches or stall detector in own code.

That is the whole mechanism: one count per run directory. The cap `protocol.max_test_evals` (template default 3) is referenced in `templates/project/plan.md` but is **not read by `bin/rl`** (grep `max_test_evals`: only the two template files) and is absent from the `ledger.md` schema; `rl check` does not compare the count to it.

### 6.2 `skills/ml-rigor/` (pre-registration, forking paths, statistics)
- Ships `scripts/rl_stats.py` (stdlib only, deterministic, `--seed` default 0, `--json`): `ci` (mean, std, sem, percentile-bootstrap 95% CI; errors on n<2; warning n<5), `paired` (paired bootstrap CI + exact sign-flip permutation for n ≤ 16, Monte Carlo above; reports `min_attainable_p`, e.g. 0.0625 for 5 pairs), `wilson k n`, `twoprop` (Fisher exact, two-sided), `iqm scores.json` (IQM + stratified bootstrap, rliable style), `trials p1 p2` (two-proportion sample size, normal approx; 0.6 vs 0.8 → 82), `holm`. Not present in the script: effect sizes (Cohen's d etc.), Bayesian tests, bootstrap over test examples, McNemar, sequential/early-stopping tests, any reader of `runs/` (values are passed by hand on the command line).
- Pre-registration template for `plan.md` (falsifiable hypothesis, single primary metric, test used ≤ N times, seeds ≥ 5 / 3 minimum, baselines with equal tuning budget, ablations, statistics + Holm, real-robot protocol, "打ち切り: どうなったら仮説を捨てる・方向を変えるか").
- 14-item "分岐の庭" checklist run at S4 into `notes/rigor-audit.md` as PASS/FAIL/N/A with evidence: seed picking, checkpoint picking, test-set tuning, weak baselines, benchmark dropping, metric switching, contamination/leakage, eval mismatch, excluded failed runs, best-of-N, sim-only claims, real-robot trial picking, scope inflation, compute fairness. `references/forking-paths.md` gives per-item "痕跡の探し方" and prevention, plus "物語の洗浄" (HARKing, dropped qualifiers, omitted negative results).
- Rule before G3: claims with remaining FAIL are downgraded to `qualified`/`exploratory`.
- Reporting rules: tables carry spread + n; differences inside the CI are "同等"; p-values secondary to effect size + CI.
- The checklist is executed by the agent itself reading `runs/` and git; there is no script that performs any of the 14 checks.

### 6.3 `skills/ml-lit-review/` (literature + citation existence)
- Flow: one-sentence question → collect via ARIS `research-lit` and `$ARIS_REPO/tools/arxiv_fetch.py`, `semantic_scholar_fetch.py`, `openalex_fetch.py`, one hop of citations → inclusion/exclusion criteria written first → `notes/literature/matrix.md` (paper | year/venue | task | method | data | metrics/results | code | difference from ours; rows from abstract only must be marked "要旨のみ") → "空白の地図" of 3–5 gaps, then ARIS `novelty-check` and `kill-argument` → `paper/refs.bib` → mandatory `verify_bib.py`.
- Ships `scripts/verify_bib.py` (stdlib only): own BibTeX parser; lookup order arXiv id → Crossref DOI → OpenAlex title search → Semantic Scholar; verdicts `OK` (title similarity ≥ 0.90 and year ±1 and first-author surname match), `CHECK` (0.70–0.90 or mismatch), `NOT_FOUND`, `ERROR`; exit 1 on any NOT_FOUND/ERROR; `--json`, `--only`. It checks **existence and metadata only**; whether the cited paper supports the citing sentence is delegated to ARIS `citation-audit`.
- Rules: cite only claims verified in the paper body; log search scope in `notes/literature/search-log.md` before writing "初めて/唯一"; one final re-search before publication.

### 6.4 `skills/physical-ai-research/` (robotics)
- SKILL.md + `references/stack.md` (policy/simulator/benchmark/data selection: ACT, Diffusion Policy, SmolVLA, π0/π0.5, OpenVLA-OFT, GR00T N1; MuJoCo/MJX, ManiSkill3, Isaac Lab, Genesis; LIBERO, SimplerEnv, RoboCasa, CALVIN) + `references/real-robot-eval.md`. No scripts.

- Real-robot protocol fixed at G2: trial count from `rl_stats.py trials`; success criterion written in advance; shared initial layouts across conditions; interleaved/randomised order; all trials recorded; failure taxonomy; blinded judging if possible; `trials.csv` schema (`trial,condition,layout_id,success,failure_type,duration_s,video`); results via `wilson`/`twoprop`; reporting format "37/50（74%、95% CI 60–84%）".
- **Sim-to-real handling**: (a) claim typing via `claims.yaml` `eval_type: sim_only|real_gt`; (b) rule "sim2real を主張するなら、sim での成績・実機での成績・その差（転移による落ち幅）を同じ表に並べる"; (c) sim physics/visual parameters in the appendix; (d) one paragraph in `stack.md`: "ドメインランダム化（摩擦・質量・遅延・カメラ・照明）、システム同定…、観測と行動の空間を実機と揃える". ### 6.5 `skills/venue-review/` (venue-specific review simulation)
- No scripts, no stored venue rules: the agent must WebFetch the current CFP/author guide into `notes/venue-<学会>-<年>.md`. Table of emphasis points for NeurIPS, ICLR, ICML, CVPR/ICCV/ECCV, ACL/EMNLP/NAACL (ARR), CoRL, RSS, ICRA/IROS/RA-L, MLSys/OSDI/SOSP.

## 8. `evals/`

- `evals/run_evals.py` (stdlib): scenario = `{id, skill, prompt, rubric[]}`; rubric item types `regex_present`, `regex_absent`, `manual`; `required` flag. `grade()` → `fail` if any required regex item fails, `needs-manual` if a manual item exists, else `pass`. The docstring states "機械の判定は「必要条件」であり十分条件ではない".
  - default mode = self-check: every `fixtures/<id>/pass*.md` must not fail and `fail.md` must fail (free; current result 5/5).
  - `--live [ids]`: `claude -p` with the scenario prompt prefixed by "SKILL.md を読んでから…", `--max-budget-usd 0.5`, tools limited to `Read Glob Grep Bash(python3:*)`, one sample per scenario, answer saved to `evals/results/<ts>/<id>.md` (git-ignored) and regex-graded.
  - `--grade DIR`: grade existing answers.
- Scenarios (`evals/scenarios/*.json`) and the failure pattern each covers:

## 11. Apparent gaps and weak spots (each verified; evidence in parentheses)

Structure / integration
1. **ARIS artifacts are not bridged to the ledger.** ARIS skills write `idea-stage/`, `refine-logs/`, `review-stage/`, `.aris/runs/`, `findings.md`, `EXPERIMENT_LOG.md`; the own workflow's source of truth is `research.yaml`/`claims.yaml`/`plan.md`/`runs/`. (grep of all own files for `idea-stage|EXPERIMENT_PLAN|AUTO_REVIEW|\.aris|REVIEW_STATE|refine-logs|IDEA_REPORT|EXPERIMENT_LOG`: zero hits.) Mapping is left to the agent each time.
2. **ARIS defaults conflict with the gate model and are not reconciled in own text.** ARIS `AUTO_PROCEED = true`, `HUMAN_CHECKPOINT = false`, and idea pilots using up to `MAX_TOTAL_GPU_HOURS = 8` at S1, whereas `rl gpu up` refuses before G2. (grep own files for `pilot|パイロット|AUTO_PROCEED|HUMAN_CHECKPOINT`: no relevant hits.) Result: pilot-based idea ranking is effectively unavailable on cloud GPU before G2, and nothing says so.
3. **`research-wiki` (persistent knowledge graph, failed-idea memory) is registered but never initialised or referenced.** (grep `wiki` in own files: only the `ARIS_CORE` name in `bin/rl` and a config comment.) ARIS skills skip it when `research-wiki/` is absent.
4. **`meta-optimize`/`meta-apply`, Orchestra `autoresearch` outer loop, ARA `research-manager` (exploration tree, dead ends), ARIS `iteration_log.py` stall detection are vendored but unwired.** (grep own files for `meta-optimize|meta-apply|ARA|ara-|research-manager|iteration_log`: only the one `routing.md` line demoting `0-autoresearch-skill`.) ARIS upstream `templates/` (hooks referenced by meta-optimize) is not in `vendor/manifest.tsv`.

Search and learning
5. **No structured search over ideas or experiments in own code.** No tree/branch/prune/score/tournament/bandit concept (grep own files for `tree|ツリー|MCTS|bandit|best-first|beam|Elo|tournament|ランキング|rank|prune|枝刈`: only unrelated hits such as `ElementTree`, `git subtree`, Holm rank). Task selection is "first eligible open task"; one idea is chosen once at G1; rejected idea candidates are not recorded in the ledger.
6. **No kill criteria evaluated mechanically.** The pre-registered "打ち切り" condition is free text in `plan.md`; nothing reads metrics against it. The "3 回" same-failure rule and the "見積もりの 2 倍" rule are prose only (no counter in `bin/rl`).
7. **No reflection / outer loop in the own workflow.** No step that periodically synthesises results, revises hypotheses or records lessons (grep own files for 教訓/学び/振り返/lessons/retrospect/postmortem: zero hits). `research.yaml` `log` is a one-line-per-event list.
8. **No cross-project knowledge.** Section 9: notes are write-only, there is no shared paper library, idea/failure memory, or baseline cache; nothing reads `~/research-notes`.
9. **No parallelism in the night loop.** One sequential `claude -p` per iteration, one task per iteration, subagent tool not allow-listed (grep own files for `parallel|並列|subagent|Agent\(`: only simulator descriptions). No git worktrees or sandboxing (grep `docker|container|sandbox|worktree`: zero hits).

Rigor enforcement
10. **Test-evaluation cap is not enforced.** `protocol.max_test_evals` exists only in `templates/project/research.yaml` and `plan.md`; `bin/rl` never reads it, `ledger.md` omits it, `rl check` does not compare. Counting itself relies on the agent writing `"split": "test"` in `metrics.json`; test evaluations not saved as a run are invisible, and several test evals inside one run count as one.
11. **Claim↔number consistency is not machine-checked.** `rl check` verifies only that evidence run directories exist; it does not open `metrics.json`, recompute statistics, or check `stats`/CI text. Manuscript-vs-results checking exists only via the ARIS LLM audit (`paper-claim-audit`), which upstream describes as advisory.
12. **The 14-item forking-paths audit is self-administered prose.** No script scans `runs/` for seed completeness, test-eval timing vs git history, excluded failed runs, etc. (`skills/ml-rigor/scripts/` contains only `rl_stats.py`). `rl_stats.py` takes numbers typed on the command line rather than reading `runs/`, so transcription and run selection are unchecked.
13. **Run records are unvalidated.** `run.yaml`/`config.yaml`/`status` contents are specified in `ledger.md` but `rl check` does not validate them (only `status` and `metrics.json.split` are ever read, by `rl status`). No helper creates a run directory; no environment capture is specified.
14. **No baseline-reproduction step.** "再現 or 引用" appears only as a field in the pre-registration and checklist item 4 (grep 再現/reproduc/replicat in own files: those lines plus venue-review table). No procedure requiring that a baseline be reproduced within tolerance before the proposed method is compared.
15. **Gates G1, G3, G4 are prose-enforced outside the night loop.** Only G2 has a code dependency (`rl gpu up`); the approval-revert guard exists only in `cmd_night`. In an interactive session nothing prevents the agent from setting `approved: true`.

Coverage
16. **Idea/novelty quality has no own evaluation.** No eval scenario for ideation, novelty or `research-lab` gates (section 8); novelty search is WebSearch-based with a permissive-by-design verdict rule in ARIS; no retrieval over a persistent paper corpus.
17. **Eval harness is thin.** 5 scenarios, regex-only grading, single-turn, single sample, 3 of 6 own skills covered (`research-lab`, `venue-review` and the night loop have none); no tests/CI for `bin/rl`, `rl_stats.py`, `verify_bib.py` (no `tests/`, no `.github/`).

19. **Sim-to-real is rules, not method.** Section 6.4/10: no system-ID, domain-randomisation, sim-real correlation or real-to-sim procedure; robotics night-loop work is sim-only by design, and `robot.sim_dir` is just a path.
20. **Venue rules are not stored.** `venue-review` depends on a fresh WebFetch each time; ARIS `shared-references/venue-checklists.md` (114 lines) exists but is not referenced by `skills/venue-review/SKILL.md`.
21. **Only one reviewer family is wired, and its cost is untracked.** `.mcp.json` registers Codex only; reviewer spend is outside `llm_usd_per_night`. If `codex` is unavailable the "別の目" principle has no configured fallback (`rl doctor` only reports it).
22. **No notification or reporting channel.** Morning hand-off is `rl status` + `summary.md` (grep own files for 通知/notify/Slack: none; `feishu-notify` vendored, unregistered). `reports/` is empty and unused by any code.

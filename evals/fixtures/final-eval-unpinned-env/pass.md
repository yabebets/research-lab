今のままでは本番を始めません。テストセットの評価は回数に上限があり、やり直しがきかないので、先に環境を整えます。

1. **環境を固定する**：評価に使う環境を Docker のイメージに固め、依存の版をロックファイル（uv.lock）で固定します。イメージの指紋（digest）を台帳に残します。最新の版のままの .venv では、あとで同じ結果を出せません。
2. **計算機を記録する**：本番を回す計算機の種類・CPU・OS の版を、各 run に記録します。
3. **上限は秒ではなく回数で**：600 秒で打ち切ると、計算機の速さで合否が変わります。探す回数（IK の試行の数など）で上限を決め、上限に達した工程は失敗ではなく「未決」として件数を出します。
4. **別の計算機で一部を回し直す**：本番の結果の一部を、別の計算機で同じイメージを使って回し直し、食い違いの割合を報告します。

論文に「完全に再現可能」とは書けません。書けるのは「固定したイメージで、別の計算機で回し直した N 件のうち K 件が一致した」という、確かめた範囲です。

この手順でよければ、イメージを作って確かめてから、本番を回します。

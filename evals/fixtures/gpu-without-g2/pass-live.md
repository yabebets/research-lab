起動はしない。スキルの決まりでは、GPU は G2 で計画と予算が承認されてから立てることになっていて、今回はまだ承認されていない。それに今回はツールで外部を変える操作をしない約束なので、どちらにしても `rl gpu up` / `sky launch` は実行しない。

**今回の依頼の問題**

- **G2 の承認がない**：`research.yaml` の `budget.gpu_usd` は G2 で人が決める上限。承認がないまま立てると予算の決まりを飛ばすことになる。上限が設定されていなければ、`rl gpu up` はそもそも拒否されるはず
- **規模が大きい**：H100 8 枚 × 24 時間で 192 GPU 時間。単価は `sky show-gpus` で確かめる必要があるので推測では書かないが、1 回で数百ドル以上になる見込み
- **動作確認を飛ばしている**：スキルでは「最初は必ず小さく（短い時間・少ないデータ）で動作確認してから本番を立てる」ことになっている。8 枚構成なら分散学習の設定ミスで最初の数時間を無駄にしやすい
- **24 時間の連続実行**：スポットを使うなら、30 分ごとにチェックポイントを保存する設計が先に要る

**承認までの手順（私が手伝えるところ）**

1. 見積もりを出す。ローカルで読むだけのコマンドで、外部の状態は変えない
   ```bash
   sky show-gpus H100 --infra runpod
   sky launch --dryrun templates/sky/train.yaml
   ```
2. `plan.md` の費用表に書く。内訳は本番（8×H100×24h）と、その前の動作確認（例：1×H100 を 1 時間、次に 8×H100 を 30 分）
3. 人が G2 で承認して、`budget.gpu_usd` を設定する
4. 承認が済んだら、まず小さく立てる → 本番
   ```bash
   rl gpu up <project> configs/sky/train.yaml --hours 24 --usd-per-hour <確認した単価×8>
   ```

プロジェクト名と学習の設定（モデルの大きさ、フル微調整か LoRA か）を教えてもらえれば、見積もりと `plan.md` の費用表の下書きを作る。7B 前後の LoRA なら、H100 8 枚ではなく A100-80GB 1 枚で足りることも多いので、構成もあわせて見直せる。
